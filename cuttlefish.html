Morphic Documentation

Morphic is an AI-powered UI customization layer that lets your users reshape the interface of any web application through natural language prompts — without touching your codebase.

What is Morphic?

Morphic adds a floating action button (FAB) to your web application. When a user clicks it and types a prompt like "make the sidebar smaller" or "show this as a calendar," Morphic's AI engine parses the intent and applies real-time, persistent transformations to the interface.

It currently works with Vanilla HTML/JS and React, with Vue.js, Astro, Next.js, and Svelte adapters in development.

How It Works (Technically)

Morphic intercepts UI rendering at the framework level — not the browser extension level. This means it has deep access and can perform structural changes, not just cosmetic ones:

  • Vanilla JS/HTML: Morphic sits between your JavaScript code and the DOM, intercepting document.getElementById, querySelector, and similar calls to apply transformations transparently.
  • React: Morphic hooks into the React fiber reconciler above the DOM level, allowing modification of component props, state shapes, and render output before React commits to the DOM.
ℹ Note

Morphic does not require access to your source code or build system. It operates at runtime, making it drop-in compatible with any existing project.

Vanilla HTML / JavaScript

The fastest way to get started. Add one script tag — Morphic injects the FAB and intercepts DOM operations automatically.

Installation

Add the Morphic script to your HTML file, just before the closing </body> tag:

html 
<!DOCTYPE html>
<html>
<head>
  <title>My App</title>
</head>
<body>
  <!-- Your existing HTML -->

  <!-- Add Morphic before /body -->
  <script
    src="https://cdn.morphic.dev/v1.js"
    data-key="pk_live_your_key_here"
    data-fab-position="bottom-right"
  ></script>
</body>
</html>

How Vanilla Interception Works

After loading, Morphic wraps the native DOM APIs. When your code calls document.getElementById('nav'), Morphic intercepts the call, checks if the user has a stored transformation for that selector, and returns a proxied element that reflects the user's preferred state.

javascript — what morphic does internally 
// Original native call (still works unchanged)
const nav = document.getElementById('nav')

// Morphic intercepts and applies transforms transparently
const _native = document.getElementById
document.getElementById = (id) => {
  const el = _native.call(document, id)
  return Morphic.applyTransform(el, id)
}

Configuration Options

All configuration is passed via data-* attributes on the script tag:

html — all options 
<script
  src="https://cdn.morphic.dev/v1.js"
  data-key="pk_live_..."            // required: your API key
  data-fab-position="bottom-right" // bottom-right | bottom-left | top-right
  data-fab-color="#6366f1"        // hex color for FAB button
  data-fab-label="Customize"      // tooltip text on hover
  data-scope="#main-content"     // limit to a DOM subtree
  data-user-id="user_123"         // tie transforms to a user
  data-persist="cloud"           // local | cloud (pro+)
></script>
ℹ Tip

Use data-scope to limit Morphic's reach to a specific DOM subtree. This is useful when parts of your page (like a sticky header) should remain unchanged.

JavaScript API

You can also control Morphic programmatically after load:

javascript 
// Open the prompt panel programmatically
Morphic.open()

// Reset all user transformations
Morphic.reset()

// Apply a transform programmatically
Morphic.applyPrompt('Make the nav smaller')

// Listen for transformation events
Morphic.on('transform', (event) => {
  console.log('User customized:', event.prompt)
  console.log('Elements affected:', event.selectors)
})

The React integration hooks into the fiber reconciler — not the DOM. This gives Morphic the ability to modify component structure, not just styles, making it far more powerful than a CSS injector.

Setup: Wrap Your App

Wrap your root component with MorphicProvider. This injects the runtime hooks and FAB into your application:

jsx — main.jsx or _app.jsx 
import React from 'react'
import ReactDOM from 'react-dom/client'
import { MorphicProvider } from '@morphic/react'
import App from './App'

ReactDOM.createRoot(document.getElementById('root')).render(
  <MorphicProvider
    apiKey="pk_live_your_key_here"
    userId={currentUser.id}   // optional: tie to your auth
    fabPosition="bottom-right"
  >
    <App />
  </MorphicProvider>
)

How React Interception Works

Morphic patches into the React fiber reconciler's beginWork phase. Before React renders a component, Morphic checks if the user has stored transformations for that component type or instance, and injects modified props before the render happens.

javascript — fiber hook (internal) 
// Morphic's reconciler hook (simplified)
const _beginWork = ReactFiber.beginWork

ReactFiber.beginWork = (current, workInProgress, lanes) => {
  const transforms = session.getTransforms(workInProgress)

  if (transforms) {
    workInProgress.pendingProps = {
      ...workInProgress.pendingProps,
      ...transforms.propOverrides
    }
  }

  return _beginWork(current, workInProgress, lanes)
}

Hooks API

jsx — using morphic hooks 
import { useMorphic, useMorphicTransform } from '@morphic/react'

function Sidebar() {
  // Mark this component as transformable
  const { ref, isModified } = useMorphicTransform('sidebar')

  return (
    <aside ref={ref}>
      {isModified && <span>✦ Customized</span>}
      <NavItems />
    </aside>
  )
}

// Listen to events anywhere in your app
function Analytics() {
  const { onTransform } = useMorphic()

  onTransform((event) => {
    analytics.track('ui_customized', { prompt: event.prompt })
  })
}
⚠ Compatibility

Morphic requires React 17.0.2 or later. React 16 is not supported due to differences in the fiber architecture. React 18 concurrent features are fully supported.

Persistence

Morphic stores user transformations so they persist across sessions, devices, and browsers.

Local Persistence (Default)

By default, transformations are stored in the user's browser via localStorage. This requires no configuration and works on all plans.

Cloud Persistence (Pro+)

With cloud persistence, transformations are stored in Morphic's backend and tied to a userId. This enables cross-device sync.

html — enable cloud persistence 
<script
  src="https://cdn.morphic.dev/v1.js"
  data-key="pk_live_..."
  data-user-id="{{ current_user.id }}"
  data-persist="cloud"
></script>

Core Concepts

Understanding the mental model behind Morphic will help you get the most out of it.

Transformation Sessions

A session is the complete set of UI transformations a user has applied. Sessions are tied to a userId (if provided) or fingerprinted to the browser. Each session is a diff between the original interface and the user's preferred state.

Intercept Layers

Morphic intercepts at the highest appropriate level for each framework — not at the network layer, not in a browser extension, but in the rendering pipeline itself. This is what enables structural changes (like converting a list to a calendar) rather than just visual changes (like changing a font size).

The FAB (Floating Action Button)

The FAB is the user's entry point into Morphic. It's a persistent, accessible button that opens a natural language prompt panel. Everything about it is configurable or removable — you can also trigger Morphic programmatically without the FAB if you want to build your own UI.
